# 大肥鱼桌宠 AI 整合版

本版本直接在原桌宠 EXE 和原 `_internal` 运行时中注入聊天模块。原程序的天气、余额、音乐歌词、形象库、应用提醒、快捷键、音效、托盘及菜单功能均保留。

## 直接运行

新版主入口位于 `dist\大肥鱼桌宠AI整合版\大肥鱼桌宠.exe`。直接双击即可，必须保留同目录的 `_internal` 文件夹，不能只移动 EXE。

推荐解压根目录的完整压缩包后运行：

```text
大肥鱼桌宠AI整合版-v3.0.2.zip
```

首次运行且不存在原桌宠配置时，默认天气地点为北京，默认尺寸为“小”（0.54）；之后仍可在原桌宠设置中修改。

完整功能和版本更新见根目录 [当前版本功能与更新说明.txt](当前版本功能与更新说明.txt)。

### 2.3.2 更新内容

- 首次运行默认尺寸由“中”调整为“小”（0.54），用户已有尺寸设置不会被覆盖。
- 新增根目录版本功能与更新说明文本。

## 大肥鱼 Agent 人设 2.1.0

桌面聊天、QQ 私聊/@ 回复、群聊主动话题和 QQ 空间草稿现在共享同一套人设：蓝色鲸鱼人鱼、活泼灵动、平时喜欢用“鱼鱼”自称、不认主人、不捧场、对世界和人类逻辑保持强烈好奇。

完整设定见 [大肥鱼人设.md](docs/大肥鱼人设.md)。

项目引用和表情素材来源见根目录 [引用说明.txt](引用说明.txt)。

### 后天成长档案

固定人设不会改变，但大肥鱼会在长期记忆整理时逐渐学习新的性格倾向、偏好、行为习惯、关系认知和世界知识。成长内容保存在 SQLite 的 `pet_persona` 与 `pet_persona_learnings` 表中，只能追加，不能覆盖核心 2.0 人设。

每次桌面聊天、QQ 回复和主动消息调用都会读取最新成长档案。可在“记忆 → 大肥鱼成长”查看成长记录，并单独清空成长档案而不影响核心人设。

## 使用聊天

- 右键桌宠，点击最上方的 **AI 聊天**，会直接打开聊天窗口。
- 也可以按 `Ctrl+Alt+C`。
- 第一次使用点击聊天窗口顶部的 **设置**。
- 默认 API 地址：`https://api.deepseek.com`
- 默认模型：`deepseek-chat`

如果原桌宠配置中已有 `ds_api_key`，整合版会自动迁移并加密保存。

### 2.3.1 聊天习惯

- AI 聊天和 QQ 回复会优先使用短句。
- 回复总长度不超过 100 字时，中文或英文逗号会变成消息分界，程序改为发送多条短消息。
- 超过 100 字时保持为一条完整消息，避免回复被拆得过碎。
- QQ 群聊和私聊的近期上下文会显示每条消息的发言者昵称。
- 昵称仅用于区分发言者，不用于分析、评价、推测身份或生成聊天对象画像。

## 图片文字与本地表情

聊天输入框旁新增 **图片** 与 **表情** 按钮。图片功能不增加视觉模型：它使用 Windows 本地 OCR 提取图片中的文字，再把文字交给当前配置的 DeepSeek 文本模型理解。纯画面、物体、人物表情等内容无法识别。

目前只支持桌面聊天选图，QQ UI 自动化无法稳定取得聊天图片原文件，因此不会假装支持 QQ 识图。

点击 **表情** 会打开项目内的相对目录：

```text
stickers\
```

直接放在 EXE 同级的 `stickers` 文件夹即可，文件名就是表情含义，例如 `开心.png`、`疑惑.gif`、`无语_翻白眼.png`。程序会将 `stickers/文件名` 作为相对地址保存。只有大肥鱼回复中出现文件名对应含义时才可能发送；默认至少间隔 3 条回复和 5 分钟，并且有多个同类图片时会轮换。

## 自动整理与记忆

数据保存在：

```text
%APPDATA%\大肥鱼桌宠\chat\
```

`memory.sqlite3` 包含自动整理的聊天画像、会话、聊天消息、长期记忆、关键消息和事件记忆。聊天界面不再要求用户手工填写画像；每次聊天会使用自动整理的稳定信息和有限的最近上下文，避免无限膨胀。

说出的称呼、偏好、目标和“请记住”内容会立即提取。达到设定间隔后，模型还会整理最近对话中的稳定信息。可通过聊天窗口顶部的 **记忆** 按钮查看和删除长期记忆。

单击、双击、拖动、打开右键菜单及执行菜单动作都会作为桌宠互动事件写入当前会话，并显示在聊天记录里。最近互动也会进入下一次聊天上下文，例如“你戳了戳大肥鱼”或“双击查看了天气”。

聊天记录同时是桌宠的行动中枢。可以直接输入：“把桌宠大小调到 60%”“透明度调到 80%”
“音量调到 50%”“锁定位置”“取消置顶”“关闭鼠标穿透”“只监听私聊”
“每 6 秒扫描 QQ”“关闭自动回复”或“我的 QQ 昵称叫 小鱼”等指令。
无法识别的请求仍作为普通聊天交给 AI。

两条正常对话消息之间的同类互动会合并显示，例如“你戳了戳大肥鱼 ×3”。
成功发送 QQ 回复后，也会在聊天页记录“回复了「会话名」”，并在同一记录段内统计消息条数。

## NapCat QQ 消息助手

3.0.0 已彻底移除通过 Windows UI 自动化操作 QQ 窗口的方式。聊天窗口顶部的 **QQ** 按钮或右键菜单的 **NapCat QQ 助手** 可以打开控制面板。3.0.1 改为原生重建 EXE，不再改写原 PyInstaller 主体，修复 Microsoft Defender 将旧整合版误判为 `Trojan:Win32/Bearfoos.A!ml` 并隔离的问题。

QQ 消息现在通过本机 NapCat 的 OneBot 11 WebSocket 收发：

- 不需要切换 QQ 会话、模拟鼠标、模拟键盘或抢占前台。
- 私聊消息会直接进入事件流。
- 群聊只处理明确 @ 当前 QQ 的消息。
- 回复通过 `send_private_msg` / `send_group_msg` 接口发送。
- 不超过 100 字的回复会拆成多个独立短消息逐条发送。
- 本地命名表情包可以通过 NapCat 图片消息段发送。

3.0.2 使用项目内已经验证可运行的 `napcat/standalone/NapCat.52230.Shell`，其中包含独立的 QQ 9.9.33、NapCat v4.18.41 和 WebUI，不再修改系统已安装 QQ 的入口文件。

首次配置：

1. 打开 **NapCat QQ 助手**，启用消息助手并填写 WebSocket 地址，默认 `ws://127.0.0.1:3001`。
2. 点击 **启动 NapCat**，桌宠会启动项目内独立的 QQ 9.9.33 + NapCat。
3. 等待 WebUI 自动打开，在 NapCat 页面完成独立 QQ 的扫码登录。
4. 勾选需要的私聊/群聊范围；确认草稿正常后再考虑开启自动发送。

自动发送仍只在本次运行期间有效，每次重启默认关闭。NapCat 的访问 Token 使用 Windows DPAPI 加密保存。NapCat 是第三方项目，使用前请阅读 `napcat/LICENSE-NapCat.txt` 与 `napcat/README-NapCat.txt`。

QQ 消息保存在同一数据库的 `qq_conversations`、`qq_messages` 和 `qq_drafts` 表中。

## 定时随机主动事件

在 **QQ 消息助手 → 随机主动事件** 页中配置。总开关默认关闭；开启后默认每 30 分钟抽取一次：

- 55%：什么也不做。
- 30%：随机打开一个群聊，结合最近聊天内容发起话题；不会基于成员昵称或头像评论，也不会 @ 或点名群成员。
- 10%：随机打开一个好友私聊。十分钟内刚聊过时延续最近话题，否则发送问候。
- 5%：生成一条 QQ 空间动态草稿，暂不实现自动发布。

总体触发概率默认 100%，表示直接按上述权重抽取。群聊、好友和空间三个事件可以分别关闭；关闭后的权重会在其余启用事件与空动作之间重新归一化。

群聊和好友事件需要先启用 QQ 消息助手。自动发送开启时才会实际发出消息；自动发送关闭时只生成草稿。QQ 空间事件无论自动发送是否开启，都只保存草稿。

主动事件草稿和历史保存在 SQLite 的 `qq_initiatives` 表中，并同步写入聊天行动记录。随机选择群聊/好友会切换 QQ 当前会话，可能把对应会话标记为已读。

## 事件记忆与聊天对象画像

桌宠会把点击、拖动、菜单操作、设置调整、QQ 回复和主动事件写入 `event_memories` 表。每次回复会读取当前聊天范围的最近事件；只有在事件与当前话题和当前聊天对象都相关时，才会自然参考。

超过 7 天的事件会被整理到 `event_memory_summaries` 表，按天保存关键事件的时间、动作和原 `event_memories` 索引。原始事件仍保留在数据库中供追溯，但压缩后的事件不再逐条进入模型上下文。

私聊联系人和在群聊中实际 @ 过大肥鱼、且能够识别出发言者的群成员会写入 `qq_user_profiles` 表。画像只包含可见消息、互动次数、@ 次数和保守的话题摘要，不推测敏感属性。可在 QQ 消息助手的 **聊天对象画像** 页查看；“记忆”窗口则新增 **事件记忆** 和 **旧事件摘要** 页。

## 隐私与密钥

- API 密钥使用 Windows DPAPI 加密，不存入 SQLite。
- 聊天会向所配置的 API 发送自动整理的画像摘要、相关记忆、最近事件和最近对话。
- 错误日志不记录 API 密钥。
- 可通过环境变量 `CHAT_PET_DATA_DIR` 使用其他数据目录，通过 `DEEPSEEK_API_KEY` 临时覆盖密钥。

## 源码结构

- `chat_pet/`：共享 Agent 人设、API、SQLite、自动记忆、PySide6 聊天界面和原程序运行时装饰。
- `napcat/`：NapCat OneBot 桥接、启动器说明和随包运行环境。
- `tools/dafeiyu_clean_entry.py`：加载原桌宠主体并安装聊天集成。
- `tools/extract_original_code.py`：从旧发布包提取原主体运行模块。
- `大肥鱼桌宠-clean.spec`：3.0.1 原生 PyInstaller 构建配置。
- `tests/`：API、数据库、记忆和端到端服务测试。

## 重新构建

3.0.1 不再改写原 PyInstaller 主体。构建环境需要使用 Python 3.12.10、PySide6 6.11.2 和 PyInstaller 6.22.x；`packaging/runtime` 保存原桌宠界面与 Qt 运行资源。

```powershell
python -m PyInstaller --noconfirm --clean .\大肥鱼桌宠-clean.spec
```

构建后把 `stickers`、`napcat/runtime`、NapCat 许可证和说明文件复制到 `dist\大肥鱼桌宠\`。不要再使用旧版直接改写原 EXE 的打包方式。
